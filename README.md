# bud-light
Reversible modification for the Budweiser Red Light, to trigger the light over local Wi-Fi using ESPHome.
The original Wi-Fi microcontroller is easily removed and not modified, and a broken out SD card connector is wired to a custom ESP32 board with display.

## The Light
The first three models of the Budweiser Red Light (v1, v2, v3) have an accessible SD card slot on the side. The one I received had the plastic cover missing, so the SD card could be clicked in and out like any normal SD card. This SD card is a Wi-Fi microcontroller, the Electric Imp imp001. Probing SD card pins with an adapter while pressing and releasing the TEST button, I discovered a pin that is directly connected to the TEST button, so this could be used to trigger the light. I decided to cannibalize a micro-SD to SD adapter, but found that two contacts on the connector are bridged. Using the pinout of the imp001 from the datasheet, I found that my micro-SD adapter bridges GND and the ID pin, which the microcontroller uses to communicate with an on-board EEPROM. To avoid potentially damaging the EEPROM, I added a small piece of tape to the ID pin contact on my adapter. I broke out the 3.3V, GND, and trigger pins for use with my custom hardware.

## Custom Hardware
I chose the ESP32-C2 for this project as I only needed Wi-Fi for this project, not Bluetooth. The C2 is low-power, so it can run on the light's D batteries but I added capacitors (10pF, 22pF, 10uF) for Wi-Fi spikes. I added a 128x32 OLED display to show either the current IP, or the captive portal's SSID and password. To save power, I added a button that can be pressed to turn the display on for a few seconds. I ordered the ESP32-C2 in ESP12 form factor and soldered it to a breakout board. I soldered the microcontroller board, capacitors, display, and button to a perfboard, designed and 3D-printed a case for housing them, and hot-glued the whole thing together.

## Software
Because this project was for a friend, I chose ESPHome for its WebUI and Wi-Fi captive portal which allow the user to easily configure/access the device from their mobile device or laptop. The Web UI allows the user to trigger the alarm, or forget saved Wi-Fi networks by factory resetting the device. If no saved Wi-Fi networks are found, the device automatically activates the hotspot and captive portal. Depending on the state of the Wi-Fi connection, pressing the button will activate the display and show either the currently connected Wi-Fi SSID and the device's IP address, or the SSID and password of the captive portal hotspot.
